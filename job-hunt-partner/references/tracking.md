# Tracking applications

The tracker answers three questions: what is live, what needs action this week, and what is working.

## Pick the tool

Use whatever the profile names. If it is a connected app (Notion, Google Sheets, Airtable), work in it directly. Before the first write, read its structure and use the user's existing property names exactly, even if they differ from the defaults below. Map their fields to these concepts rather than adding new ones.

If the user has no tracker, offer one: a spreadsheet they can keep, or a database in a tool they already use. Ask which before building.

## Default fields

| Field | Notes |

| Company | Title field |
| Role | Exact title from the posting |
| Status | See statuses below |
| Score | 0 to 100 from the evaluation |
| Recommendation | Strong match, Worth applying, Possible but low priority |
| Location policy | The company's own words |
| Pay | Published band, or "Not disclosed". Never an estimate. |
| Link | Direct posting URL |
| Source | Where it was found |
| Date found | |
| Date posted | If known |
| Date applied | |
| Contacts | Name, role, profile link, relationship, one line each |
| Messages | Drafts for each contact, with send order and character counts |
| Next action | One action |

| Verdict | The short verdict from the evaluation, including "Do not claim" |

## Statuses

To review, Ready to apply, Applied, Interviewing, Offer, Rejected, Withdrawn, Closed.

Change status only on evidence. "Rejected" means the company said no. "Withdrawn" means the user pulled out. "Closed" means the posting came down with no answer. Mark a role "Closed" after about four weeks of silence with no live contact, so the board reflects reality.

## Rules

- **Log only roles worth pursuing**, unless the profile says to log rejected ones too. Roles that fail a gate are reported in chat and left out, so the tracker stays a list of real options.
- **Deduplicate** on company plus role plus link. Update an existing row rather than adding a second one.
- **Every row has a next action and a date.** A row without one is either finished or forgotten.
- **Do not overwrite the user's edits.** If a field they changed conflicts with new information, ask.

## Follow-up rhythm

- **Applied, with a contact:** follow the outreach sequence in outreach.md.
- **Applied, no contact:** if nothing has happened after 7 to 10 days, look for one person to contact (the recruiter or hiring manager) and draft a rung 0 message.
- **After an interview:** a short thank-you note within 24 hours, with one specific point from the conversation. Then follow up once at the date they gave, or after about a week if they gave none.

## Weekly review

When the user asks how the search is going, or once a week if they want a routine, report:

1. **This week:** applications sent, messages sent, replies, interviews.
2. **Due now:** every row whose next action date has passed.
3. **Conversion by stage:** applied to reply, reply to interview, interview to offer. Break it down by source (referral, cold outreach, direct apply) once there are enough rows to compare.
4. **The diagnosis.** Use the stage where things stall to decide what to fix:
   - Few replies after a meaningful number of applications usually points to targeting or the resume. Re-check the gates and run a resume audit.
   - Replies but few interviews points to the first conversation: how they pitch themselves, and pay or location mismatches surfacing late.
   - Interviews but no offers points to interview prep or level mismatch.
   - Direct applications with no response while referrals convert means shifting time to outreach.

Keep it to what the numbers show. Small samples are noisy, so say so when there are too few rows to conclude anything.
